# PulseOps

Kubernetes 기반 모니터링 백엔드에 연결하는 단일 페이지 웹사이트 모니터링 대시보드입니다.
React 19, TypeScript, Vite, Tailwind CSS v4, Recharts, Lucide React를 사용합니다.
전역 상태 라이브러리 없이 React hooks와 Fetch API로 구성했습니다.

## 실행

Node.js 22.12 이상과 pnpm이 필요합니다.

```powershell
pnpm install
Copy-Item .env.example .env.local
pnpm dev
```

- 프론트엔드: http://localhost:5173 (포트가 사용 중이면 종료하므로 다른 포트의 CORS 혼동을 방지합니다.)
- Spring Boot: http://localhost:8080
- 환경변수: `VITE_API_BASE_URL=/api`
- 환경변수를 변경하면 Vite를 재시작하세요. 배포 빌드에는 빌드 시점 값이 포함됩니다.
- 환경변수를 생략하거나 비워도 기본값 `/api`를 사용합니다. 브라우저는 현재 origin의 `/api/v1/...`로 요청하며 Pod IP나 고정 서버 주소를 사용하지 않습니다.
- 로컬 개발에서는 Vite의 `/api` 프록시가 경로를 변경하지 않고 `http://localhost:8080` 백엔드로 전달합니다. 운영 환경에서는 동일 origin의 `/api`를 백엔드로 라우팅해야 합니다. Vite 개발 프록시는 빌드 결과에 포함되지 않습니다.

## 검사 및 빌드

```powershell
pnpm typecheck
pnpm test
pnpm build
pnpm preview
```

빌드 결과는 `dist/`에 생성됩니다. 차트는 별도 번들로 지연 로딩합니다.
기존 ESLint 설정에 맞춰 신규 파일의 정적 검사를 수행했습니다.
API 클라이언트 테스트는 Node 내장 테스트 러너와 이미 설치된 TypeScript만 사용합니다.
테스트 fixture는 테스트 실행 안에서만 사용하며 앱에는 샘플 데이터나 성공 fallback이 없습니다.

## 주요 구조

```text
src/
  main.tsx                     # 단일 페이지 진입점, StrictMode
  app/App.tsx                  # 대시보드 구성
  components/
    Header.tsx                 # 브랜드, 마지막 목록 갱신 시각, 새로고침
    SummaryCards.tsx           # 전체 / UP / DOWN
    SiteForm.tsx               # 등록 및 입력 검증
    SiteList.tsx               # 사이트 선택, 주기 변경, 삭제
    StatusBadge.tsx            # 상태 텍스트 및 색상
    ResponseTimeChart.tsx      # Recharts 차트, 기간 선택, 실패 목록
  services/siteApi.ts          # API 호출, 응답 정규화, 오류 처리
  hooks/useSites.ts            # 데이터, 선택 상태, 30초 갱신, 요청 취소
  types/site.ts                # API 타입 및 지원 검사 주기
  utils/format.ts              # 날짜, 응답 시간, 오류 포맷
  styles/index.css             # Tailwind v4 및 반응형 다크 테마
tests/siteApi.test.mjs          # API 계약, null, 오류, 요청 취소 검사
```

기존 템플릿의 공통 컴포넌트 및 레이아웃 파일은 보존했지만 현재 진입점에서는 사용하지 않습니다.
로그인과 별도 페이지 라우팅은 사용하지 않습니다.

## API 계약

| 작업 | 엔드포인트 | 요청 |
| --- | --- | --- |
| 목록 | GET /api/v1/sites | 없음 |
| 등록 | POST /api/v1/sites | name, url, intervalSeconds |
| 주기 변경 | PATCH /api/v1/sites/{id} | intervalSeconds |
| 삭제 | DELETE /api/v1/sites/{id} | 없음 |
| 이력(분) | GET /api/v1/sites/{id}/history?minutes=5 | minutes: 1, 5, 30 |
| 이력(시간) | GET /api/v1/sites/{id}/history?hours=24 | hours: 1, 6, 24 |
| 전체 이력 | GET /api/v1/sites/{id}/history?all=true | hours/minutes와 함께 전송하지 않음 |

지원 주기는 60 / 300 / 600초입니다. 등록 시 이름, HTTPS URL, 주기를 검증합니다.
차트 버튼은 조회 기간이 아닌 X축 눈금 간격(1분 / 5분 / 30분 / 1시간 / 6시간 / 24시간)을 선택합니다.
X축에는 선택한 간격의 6칸과 7개 눈금을 표시합니다. 예: 1분 간격은 약 6분, 5분은 약 30분, 24시간은 약 6일입니다.
눈금은 브라우저 현지 시간의 정각·정분에 맞춥니다. 오른쪽 끝은 현재 시각 다음 눈금이며, 날짜를 넘는 범위에는 MM/DD를, 24시간 간격에는 날짜를 표시합니다.
차트는 가로 스크롤 없이 화면 너비에 맞춥니다. 좁은 화면에서는 첫·마지막 라벨을 유지하며 겹치는 중간 라벨을 생략합니다. 범위 밖 데이터는 차트·검사 건수에서 제외하며 실제 검사값을 임의로 집계하지 않습니다.
표시에 필요한 이력은 1분 간격에 minutes=30, 5분에 hours=1, 30분·1시간에 hours=6, 6시간·24시간에 all=true로 조회합니다.
백엔드가 24시간 초과 기간 조회 파라미터를 제공하지 않아 일 단위 표시에는 전체 이력을 받아 화면 범위로 제한합니다. 데이터가 커지면 백엔드의 from/to 또는 일 단위 조회 API로 전환하는 것이 좋습니다.
백엔드 소스에서 minutes와 all=true 지원을 확인했습니다. 실행 중인 localhost:8080 OpenAPI에는 아직 hours만 노출되어 있어 최신 백엔드 소스로 재시작해야 합니다.
사이트 배열과 `{siteId, history: [...]}` 형식을 기준으로 하며, 클라이언트 계층에서
`data` wrapper와 목록의 `content` / `sites` 배열도 처리합니다.
수정·삭제 성공 응답은 빈 본문도 지원합니다.
에러 JSON의 message 및 HTTP 상태 코드를 표시합니다.

브라우저 직접 연결 시 백엔드는 origin `http://localhost:5173`, 메서드
GET / POST / PATCH / DELETE / OPTIONS, 헤더 Content-Type을 허용해야 합니다.

## 화면 및 데이터 동작

- 시작일·종료일 DatePicker 두 개로 기간을 지정하고 조회 버튼으로 적용합니다. 날짜 선택만으로 API를 호출하지 않습니다. 종료일의 하루 전체를 포함하며 브라우저 현지 시간으로 처리합니다.
- 기본 모드는 날짜가 비어 있는 실시간 조회입니다. 기간 지정 중에는 차트 이력의 자동 갱신을 멈추고 사이트 목록만 계속 갱신합니다. 수동 새로고침으로 지정 기간 이력을 다시 조회할 수 있습니다.
- 초기화는 날짜·검증 메시지를 비우고 기본 24시간 눈금 및 실시간 이력 자동 갱신으로 복귀합니다. 선택한 사이트는 유지합니다.
- 현재 백엔드에 from/to API가 없어 지정 기간은 all=true로 조회 후 API 클라이언트에서 날짜로 필터링합니다. 넓은 날짜 범위의 축 라벨은 선택 간격의 배수로 조정하고 안내하며 실제 검사 데이터는 집계하지 않습니다.
- UNKNOWN은 전체 개수에만 포함하며 아직 검사되지 않은 사이트는 검사 대기로 표시합니다.
- 목록 앞 체크박스로 여러 사이트의 응답 시간을 한 차트에서 비교합니다. 전체 선택·해제와 부분 선택 표시를 지원합니다. 체크박스는 차트 비교 대상이며 백엔드 enabled 값을 변경하지 않습니다.
- 처음 사이트가 생기면 첫 사이트를 기본 선택하고, 사용자가 전체 해제한 뒤에는 자동 갱신으로 다시 선택하지 않습니다. 삭제된 사이트는 선택과 차트에서도 제외합니다.
- 사이트를 추가 체크할 때는 새 사이트 이력만 조회하며 기존 선을 유지합니다. 선택 해제 또는 기간 변경 시 불필요한 요청을 취소하고 이전 응답을 무시합니다. 개별 사이트의 조회 실패는 해당 사이트명과 함께 표시하며 다른 사이트의 차트를 유지합니다.
- 상단의 '사이트 추가' 버튼을 누르면 공통 Popup에서 이름·HTTPS URL·검사 주기를 입력합니다. 등록 중에는 닫기와 중복 제출을 차단합니다. 성공하면 팝업을 닫고 입력을 초기화하며, 실패하면 팝업과 입력을 유지합니다. 취소 후 다시 열어도 작성 중인 내용은 유지됩니다.
- 최초 조회 실패 시 요약을 0으로 오인하지 않도록 대시(—)를 표시합니다.
- 목록과 선택 사이트 이력을 자동 갱신합니다. 갱신 완료 후 30초를 예약하며, 수동 갱신·등록·수정·삭제 후에는 타이머를 다시 시작합니다.
- 이미 진행 중인 동일 조회를 중복 실행하지 않고, 15초에 요청 시간을 제한합니다.
- 사이트·기간 변경 및 언마운트 시 진행 요청을 취소해 이전 응답이 새 선택을 덮어쓰지 않게 합니다.
- 등록·수정·삭제는 기존 목록 조회가 완료된 뒤 실행하고, 성공 후 목록을 한 번 다시 조회합니다. 변경 작업 중 수동·자동 갱신과 중복 제출을 차단합니다.
- StrictMode의 초기 Effect 재실행에서 실제 HTTP 요청이 중복되지 않도록 초기 조회를 취소 가능한 타이머로 예약합니다. StrictMode는 유지합니다.
- 등록·수정·삭제 결과는 기존 공통 Toast를 재사용하여 우측 상단에 표시합니다. 성공은 3초, 오류는 5초 후 닫히며 직접 닫을 수도 있습니다.
- 변경 작업 중 중복 제출을 막고, 삭제 전에 공통 Confirm 팝업에 사이트명과 URL을 표시합니다. 취소·Escape·바깥 영역으로 닫을 수 있고, 삭제 중에는 닫기와 중복 요청을 차단합니다. 실패 시 팝업에서 재시도할 수 있으며 결과는 Toast로 표시합니다.
- 자동 갱신 중에는 입력값, 기존 목록과 차트를 유지합니다. 오류 발생 시 이전 데이터임을 알립니다.
- 응답 시간 null은 0으로 변환하지 않고 선을 끊습니다. DOWN 검사는 빨간 점선과 실패 상세 목록으로 표시합니다.
- 데이터가 없거나 네트워크 요청이 실패해도 가짜 모니터링 데이터를 생성하지 않습니다.
- 날짜는 브라우저의 현지 시간대를 사용합니다.
- 모바일은 단일 열과 표 가로 스크롤을 사용하며 버튼·입력의 터치 영역을 확보합니다.
- 웹소켓, 로그인, 결제, 사용자 관리, 알림 연동은 구현 범위에 포함하지 않습니다.

## 요청 중복 및 Toast 브라우저 회귀 검사

개발 서버 실행 후 별도 터미널에서 실행합니다. 추가 테스트 라이브러리 없이 로컬 Chrome 또는 Edge의 headless 모드를 사용합니다.

```powershell
pnpm test:browser
```

브라우저 경로가 다르면 CHROME_PATH, 개발 서버 주소가 다르면 TEST_ORIGIN 환경변수를 설정하세요.
API 응답과 30초 폴링 시간은 격리된 테스트 탭에서만 대체하므로 실제 백엔드 데이터를 변경하지 않습니다.

검증한 항목:

- StrictMode 최초 진입: 빈 목록은 목록 GET 1회, 기존 사이트가 있으면 목록 GET 및 이력 GET 각각 1회.
- 중복 제출·수동 갱신·폴링 충돌: POST 1회, 등록 후 목록 GET 1회, 선택 사이트 이력 GET 1회.
- 자동 갱신: 목록·이력 각각 1회 및 작성 중인 입력 유지, 다음 폴링 타이머 1개 유지.
- 성공 Toast 표시 및 자동 닫기, 등록 오류 Toast 표시 및 수동 닫기, 실패 시 입력 유지.
- 삭제 Confirm 팝업 열기·취소·Escape·포커스 복원, 실패 후 재시도, 삭제 중 닫기 차단, DELETE 중복 방지 및 성공 Toast.
- 등록 Popup의 입력 검증·자동 포커스·Escape 닫기·포커스 복원, 등록 중 닫기 차단, 성공 후 닫기·초기화, 실패 및 취소 후 입력 유지.
- DatePicker 날짜 선택과 조회 적용 분리, 종료일 포함 및 인접 날짜 제외, 지정 기간 차트 갱신 중지, 초기화 시 날짜 비우기·기본 눈금·실시간 이력 자동 갱신 복귀.
- 다중 사이트 선택 시 신규 사이트만 조회, 실제 SVG의 사이트별 시리즈와 null 제외 확인, 6개 조회 기간의 정확한 파라미터와 요청 수 확인.
- 전체 선택·해제, 해제 후 자동 갱신에서 재선택하지 않음, 해제 시 진행 요청 취소 및 오래된 응답 차단, 일부 사이트 오류 격리와 새로고침 복구.

실제 30초 대기 대신 테스트 탭의 폴링 타이머를 진행시켜 검증합니다. 모바일 스크린샷과 실제 누적 데이터의 차트 시각 검증은 수행하지 않았습니다.
